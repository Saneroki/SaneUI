# Sync (part of Core)

## Files (`src/Core/Sync/`, in Core's TOC; `Core.Sync`, called `Sync` in them)

| File | Responsibility |
| --- | --- |
| `Sync.lua` | `Core.Sync`, `GROUPS`, part registry (`Sync.Part(id, group, part)`), Capture/Give, kept-by-name CVars, timing (Core's events), `Core.Options` for `off`/`taken`/`named` |
| `Data/Pages.lua` | Generated by `dev/tools/sync-pages` (`--check`) from Blizzard's options code: `Sync.PAGES` = per Gameplay/Accessibility page `{ page, group, cvars, flags, clicks, bars }` |
| `Layout.lua` | Edit Mode layout in use (`hudLayout`) |
| `Chat.lua` | Own channels (`ownChannels`, registered before windows) and chat windows with places and chat colours (`chatFrames`) |
| `Game.lua` | Page parts from `Sync.PAGES`; Graphics/Audio by console category; `perCharacter` (CVars `GetCVarInfo` says are stored per character, on no page); `Sync.SetCVar(name, value)`, every CVar write of Sync |

## Contracts

- No module (no `SaneUI.Sync`), so no page; `Settings/Synced.lua` builds the tab *Game settings*: one box per
  `Sync.GROUPS` entry (`SETTING_GROUP_GAMEPLAY`, `_ACCESSIBILITY`, `_SYSTEM`, `elsewhere`) with a
  checkbox per part of that group (`Sync.PartKept` / `Sync.KeepPart`). Group and page titles are the game's
  strings (`Sync.Word(name, fallback)`, the same function as `Core.Word`).
- Only with *Accountwide settings* on (`Core.Profiles.On()`): off, `Give` and `Capture` do nothing and Sync's settings
  are a table of the session (Core.Options hook `game = true`).
- Saved (`Core.Settings("Sync")`, in the profile in use only, never a character's own): `off[id] = true`
  (part left to the game; every part kept by default, new ones too), `taken[id] = data`, `named[cvar] = value`
  (`Sync.Keep`/`Sync.Kept`, used by Settings' CVar list). No upgrade code: earlier shapes are ignored.
- Part = `{ id, group, text, tip, reload?, Read() -> data, Write(data) -> needsReload }`, in `Sync.parts` in file
  order (Layout, Chat, Game). `Sync.Capture` (Core's `capture`, before every snapshot) rebuilds `taken` from kept
  parts (a failing Read keeps the old data) and refreshes `named`; it does nothing until `Sync.Give` ran this
  session. `Sync.Give`: 2 s after first PEW once `C_CVar.AreCVarsLoaded()` (else 2 s after `VARIABLES_LOADED`),
  after combat if needed, and on the `moved` hook (another profile used, Accountwide switched on), once the
  first writing came due (`settled`); writes only table data, only
  differences; one reload dialog per writing (`Sync.OfferReload` → `Core.AskReload`) naming parts whose Write
  returned true (Edit Mode, also a waiting layout set later; chat windows/colours; action bars).
- Page parts write only CVars of their own list that the client has; flags/clicks the game does not answer keep
  the old value. Every CVar write (parts, `named`) is `Sync.SetCVar`: only a value (text) that differs, not a
  CVar `GetCVarInfo` says is locked or read only, a secure one not in a fight (`SetCVar` is
  `RequiresNonReadOnlyCVar`/`RequiresNonSecureCVar`), in a `pcall`; one the game does not take (an error, or
  it keeps its value) is noted once (`Core.NoteError`, label `Sync: setting CVars`) and not tried again this
  session; the loop goes on.
- Graphics/Audio/perCharacter are found once per session by the scheduler's job `Sync: the game's CVars`
  (`Core.Steps`, started by the first Read or Write: the list from `ConsoleGetAllCommands` in a frame of its
  own, then a `GetCVarInfo` per CVar within the budget), excluding page CVars, `STATE` and `MACHINE` patterns,
  and CVars locked, secure or read only. Until found (and when the game cannot list) Read keeps `taken`; Write
  keeps its data as `pending`, which the job writes before the names count as found.
- Saved data is checked for its kind before use: a chat window's switches (boolean), dock (number or false),
  tint and place (numbers), kinds and channels (text), a colour's `r`/`g`/`b`; the bars per entry (one the
  list lacks or not boolean stays as the game has it). A value of another shape leaves that setting alone.
- Never touch Blizzard chat/action/Edit Mode frames: only stored-setting APIs (`SetChatWindow*`,
  `Add/RemoveChatWindow*`, `ChangeChatColor`, `SetActionBarToggles`, `C_EditMode.SetActiveLayout`,
  `SetModifiedClick` + `SaveBindings`).

Edit Mode: never read the active layout at logout (the game reports its first preset then). `Layout.lua` keeps
`seen` (read from `EditModeManagerFrame.layoutInfo` a frame after `EDIT_MODE_LAYOUTS_UPDATED` and on read, only
while in the world: PEW → PLAYER_LEAVING_WORLD), `waiting` (not set yet: no manager layouts, Edit Mode open
(`Core.EditMode.active`), combat; retried on those events and when `Core.EditMode.Watch` says closed) and
`missing` (kept, but not in this character's list: kept until the layout in use changes while in the world
and not by us, the player's pick; so a character without another's own layout does not overwrite the choice
at its logout). Read = waiting or missing or seen or what was taken.

Regenerate `Data/Pages.lua` after a client update: `dev/tools/sync-pages` (reads `references/`, camelot game type,
Mainline family; Gameplay order from `CUSTOM_GAMEPLAY_SETTINGS_ORDER`).

Tests: `dev/tests/sync.lua` (model of chat windows, own channels, Edit Mode with the logout loss and a missing
layout, bars, modifier keys, scoped CVars, per-character discovery as a job, CVars the game does not let us
set, spoiled and older-shape data, kept-by-name CVars, profiles).
