# Sync (part of Core)

## Files (`src/Core/Sync/`, in Core's TOC; `Core.Sync`, called `Sync` in them)

| File | Responsibility |
| --- | --- |
| `Sync.lua` | `Core.Sync`, `GROUPS`, part registry (`Sync.Part(id, group, part)`), Capture/Give, kept-by-name CVars, timing (Core's events), `Core.Options` for `off`/`taken`/`named` |
| `Data/Pages.lua` | Generated by `dev/tools/sync-pages` (`--check`) from Blizzard's options code: `Sync.PAGES` = per Gameplay/Accessibility page `{ page, group, cvars, flags, clicks, bars }` |
| `Layout.lua` | Edit Mode layout in use (`hudLayout`) |
| `Chat.lua` | Own channels (`ownChannels`, registered before windows) and chat windows with places and chat colours (`chatFrames`) |
| `Game.lua` | Page parts from `Sync.PAGES`; Graphics/Audio by console category; `perCharacter` (CVars `GetCVarInfo` says are stored per character, on no page) |

## Contracts

- No module (no `SaneUI.Sync`), so no page; `Settings/Synced.lua` builds the tab *Accountwide*: box Sane UI, then
  one box per `Sync.GROUPS` entry (`SETTING_GROUP_GAMEPLAY`, `_ACCESSIBILITY`, `_SYSTEM`, `elsewhere`) with a
  checkbox per part of that group (`Sync.PartKept` / `Sync.KeepPart`). Group and page titles are the game's
  strings (`Sync.Word(name, fallback)`).
- Saved (`SaneUIDB.modules.Sync.options`, ride along with account/character/profile settings): `off[id] = true`
  (part left to the game; every part kept by default, new ones too), `taken[id] = data`, `named[cvar] = value`
  (`Sync.Keep`/`Sync.Kept`, used by Settings' CVar list). No upgrade code: earlier shapes are ignored.
- Part = `{ id, group, text, tip, reload?, Read() -> data, Write(data) -> needsReload }`, in `Sync.parts` in file
  order (Layout, Chat, Game). `Sync.Capture` (Core's `capture`, before every snapshot) rebuilds `taken` from kept
  parts (a failing Read keeps the old data) and refreshes `named`; it does nothing until `Sync.Give` ran this
  session. `Sync.Give`: 2 s after first PEW once `C_CVar.AreCVarsLoaded()` (else 2 s after `VARIABLES_LOADED`),
  after combat if needed, and on `changed("taken")` (profile load / own switch); writes only table data, only
  differences; one reload dialog per writing (`Sync.OfferReload` → `Core.AskReload`) naming parts whose Write
  returned true (Edit Mode, also a waiting layout set later; chat windows/colours; action bars).
- Page parts write only CVars of their own list that the client has; flags/clicks the game does not answer keep
  the old value. Graphics/Audio/perCharacter resolve once per session via `ConsoleGetAllCommands` (+
  `GetCVarInfo`), excluding page CVars, `STATE` and `MACHINE` patterns; when the game cannot list, Read keeps
  `taken`.
- Never touch Blizzard chat/action/Edit Mode frames: only stored-setting APIs (`SetChatWindow*`,
  `Add/RemoveChatWindow*`, `ChangeChatColor`, `SetActionBarToggles`, `C_EditMode.SetActiveLayout`,
  `SetModifiedClick` + `SaveBindings`).

Edit Mode: never read the active layout at logout (the game reports its first preset then). `Layout.lua` keeps
`seen` (read from `EditModeManagerFrame.layoutInfo` a frame after `EDIT_MODE_LAYOUTS_UPDATED` and on read, only
while in the world: PEW → PLAYER_LEAVING_WORLD) and `waiting` (not set yet: no manager layouts, Edit Mode open,
combat; retried on those events and `EditMode.Exit`). Read = waiting or seen or what was taken.

Regenerate `Data/Pages.lua` after a client update: `dev/tools/sync-pages` (reads `references/`, camelot game type,
Mainline family; Gameplay order from `CUSTOM_GAMEPLAY_SETTINGS_ORDER`).

Tests: `dev/tests/sync.lua` (model of chat windows, own channels, Edit Mode with the logout loss, bars, modifier
keys, scoped CVars, per-character discovery, spoiled data, kept-by-name CVars, profiles).
